# 中车眼镜安全自动标注与训练闭环设计

## 决策

采用“多信号共识 + Codex视觉仲裁 + 不确定样本隔离”的安全自动化路线。系统自动处理现场全图、生成
候选、发现漏框、修正框、建立AI银标数据集并训练移动端检测模型；任何模型或Codex都无法可靠判断的
目标必须保留为`UNCERTAIN`，不得为了覆盖率强行写入训练真值。

本闭环的目标是最大限度减少人工逐框标注，不把AI银标伪装成人工真值。由AI银标得到的验证指标只能
用于模型间内部比较；没有独立真实标注或现场抽检前，不报告生产准确率。

## 范围与交付

本阶段自动处理Git外482张现场照片，交付以下链路：

1. 多尺度、重叠切片和多来源候选召回；
2. 同场景邻帧几何传播与候选融合；
3. 面向Codex的候选级、整图级视觉审核资产和机器可读决定；
4. 自动补框后的二次渲染与复审；
5. 可训练AI银标集、隔离的不确定集和完整审计清单；
6. 达门后训练PicoDet-S/M，最多三轮学生模型再扫描；
7. 必要时加入有来源约束的imagegen合成增强；
8. Git外模型、数据、图片和报告，以及Git内代码、测试、规格和不含现场内容的统计。

本阶段不把参考YOLOv8s权重作为生产模型，不自动宣称松动状态准确率，也不在缺少目标手机时宣称
手机P95达标。

## 自动处理架构

### 1. 资产冻结与场景隔离

系统以现有图片清单、177个场景组和确定性train/val划分为输入。每次运行先记录源图、选择清单、
教师权重、配置和正式真值的SHA-256。相邻帧只能在同一场景组内传播；一个场景组不得跨train/val。

所有自动输出写入新的Git外run目录。原始教师预测、已有正式真值和上一次审核决定均只读，脚本执行
前后验证正式真值字节哈希不变。

### 2. 多来源候选召回

每张图生成以下独立候选：

- 参考YOLOv8s教师在完整图和640、960、1280三个固定输入尺寸上推理；
- 2×2、12%重叠切片推理并映射回原图坐标；
- HSV红色/黄色防松标记定位产生的物理紧固件邻域候选；
- 同场景高相似邻帧通过稳健特征匹配和几何变换传播的候选；
- 后续轮次PicoDet-S/M学生模型产生的候选。

每个候选记录稳定ID、源图、场景组、原图坐标、类别建议、各来源置信度、尺度、切片、传播来源、
几何变换质量和模型/配置哈希。任何坐标必须裁剪到图像范围内，空框和退化框直接拒绝。

### 3. 候选融合

默认先按类别建议和IoU 0.55聚类，再用加权框融合生成共识框；跨类别且IoU不低于0.55的候选直接
标记为冲突。融合不得丢弃原始候选；共识记录完整成员列表。阈值只能通过版本化配置修改。

自动进入Codex审核前，每个共识框分为：

- `consensus_high`：至少两个独立来源族支持，且无明显类别或几何冲突；
- `single_source`：只有一个模型或一种信号支持；
- `conflict`：来源对类别、位置或目标存在性判断不一致；
- `propagated`：主要来自邻帧传播，必须核验当前帧可见性。

类别映射继续保留`inferred_unconfirmed`，直至Codex通过原图语义核实。融合分数不是训练真值置信度。
不同尺寸或切片上的同一个YOLO教师仍属于同一来源族；独立来源族固定为参考教师、HSV、邻帧传播和
后续学生模型，禁止用同一模型的多尺度重复命中伪造“多模型共识”。

## Codex视觉仲裁

### 审核输入

每张图自动生成：

- 保持原分辨率比例的整图叠加图；
- 带规范化坐标网格的整图分区图；
- 每个候选包含上下文的局部裁剪；
- 同场景邻帧并排图；
- 来源、分数、类别冲突和历史决定摘要。

审核资产必须只包含任务所需的现场图和机器数据，不将会议记录或其他私人文档混入提示。

### 审核输出

Codex对候选输出`accept / reject / needs_adjustment / uncertain`，并记录理由。对整图输出：

- 已接受目标是否存在重复框；
- 是否发现未框紧固件或管接头；
- 漏检目标的`[0,1]`规范化`xyxy`初始框和类别建议；
- 当前图是否达到`complete / uncertain`。

Codex补框不能一次进入银标。系统把初始框重新渲染成高分辨率叠加图，进行第二次视觉检查；第二次
使用不同提示模板且不展示第一次结论，只能确认、修正或退回`UNCERTAIN`。审核决定记录审核器标识、
两次提示模板版本、输入资产哈希和时间。

### 冲突规则

多信号无法达成一致时由Codex仲裁。Codex可以明确接受、拒绝或修正；如果目标遮挡严重、过曝、失焦、
类别无法区分或框边界无法可靠确定，则必须输出`UNCERTAIN`。系统没有“默认接受”分支。

## AI银标真值门

候选级接受不等于整图完成。图片只有同时满足以下条件才能进入AI银标训练集：

1. 所有候选均已得到最终决定；
2. 所有Codex补框均通过二次渲染复审；
3. 整图扫描没有未处理漏检；
4. 图片中不存在`UNCERTAIN`目标；
5. 同场景传播没有未解决冲突；
6. 图像和标注坐标、类别、面积及引用关系全部合法。

无目标图片只有经过整图审核并明确`accept_empty`才可作为困难负样本。未通过的图片进入不确定集，
不计入训练场景数，也不转换为负样本。

训练入口至少要求80个完成场景组，其中train不少于64组、val不少于16组；同时要求场景组零泄漏、
至少一个接受框和全部输入哈希匹配。AI银标必须存放在独立路径，不覆盖人工正式真值。

## 自动训练与迭代

首轮同时训练PicoDet-S 416和PicoDet-M 416。二者使用相同银标、增强、切片和评估配置。内部比较关注：

- AI银标验证集上的目标召回、精确率和每图误报；
- 小目标、模糊、过曝、遮挡和密集管路分桶表现；
- 模型大小、导出成功性和桌面运行时延迟；
- 指定Android手机可用后，相同预处理和切片策略下的端到端P50/P95。

较优学生模型重新扫描全部482张，与教师、HSV和邻帧候选比较。新分歧进入Codex仲裁，再生成下一轮
银标并训练。最多运行三轮。默认收敛条件为：相邻两轮新增接受框不超过上一轮接受框总数的1%，且
未解决冲突数不增加；阈值写入版本化配置。任一轮AI银标val召回下降超过2个百分点或每图误报增加
超过10%，视为性能恶化并回退该轮。三轮后仍不收敛、完成场景组不足80或验证性能恶化时自动停止并
写拒绝报告，不导出“生产可用”结论。

## 合成与增强策略

优先使用确定性的真实目标复制粘贴、尺度、曝光、模糊、噪声和局部遮挡增强。只有真实数据在某个已
量化失败分桶中不足时才调用imagegen。

imagegen使用真实裁剪作为参考，主要补充极端光照、污渍、遮挡、拍摄角度和少见防松标记外观。生成
样本必须保存提示、参考图哈希、生成方式和审核结果。合成图片只进入train，占有效训练图片上限20%；
val和最终现场验证保持100%真实图片。

涉及防松线错位、断裂或缺失的生成图只用于增强外观鲁棒性，不作为物理松动真值依据。无法保持部件
结构或标记几何的生成结果由Codex拒绝，不进入训练。

## 可复现性与错误处理

- 所有选择、切片、融合和数据导出使用固定seed和版本化配置；相同输入重复运行产生相同机器候选。
- 单图解码失败或模型推理失败时记录错误并继续，但该图强制进入不确定集。
- 特征匹配内点不足、变换越界或尺度异常时禁止邻帧传播。
- Codex输出缺字段、坐标非法或引用不存在时拒绝整份决定并重新生成审核任务。
- 依赖、权重或导出资产哈希不匹配时立即停止对应阶段。
- 不确定样本、失败样本和被拒候选都保留审计证据，不静默删除。

## 测试与验证

### 单元测试

- 多尺度与切片坐标反变换、边界裁剪和确定性；
- 候选聚类、加权框融合和来源保留；
- 邻帧变换质量门、传播坐标和跨场景拒绝；
- Codex审核JSON契约、补框二次复审和非法决定拒绝；
- 银标图像完整性门、`UNCERTAIN`隔离和场景泄漏检查；
- 合成样本比例、来源记录和验证集禁入；
- 三轮收敛、恶化停止和拒绝报告。

### 集成验证

- 在固定小样上完整运行“召回—融合—审核任务—决定合并—银标导出”；
- 对已有100图教师run复放，确认原始731候选和正式真值哈希不变；
- 对无框、密集目标、边缘目标、强光和模糊图片验证安全失败；
- 达门前训练命令绝不启动，达门样例生成确定的训练manifest；
- PicoDet导出模型完成桌面加载和至少一张全图加切片推理冒烟测试。

## 完成标准

- 482张图片均有机器处理记录，失败和不确定项无遗漏；
- 候选和Codex决定具备一一对应、可追溯来源与稳定哈希；
- 至少80个场景组达到AI银标整图完整门，否则输出明确停止报告；
- train/val场景泄漏为0，val合成图为0；
- 训练最多三轮且每轮数据、配置、模型和指标可复现；
- 正式人工真值始终未被自动流程覆盖；
- 所有指标明确标记为AI银标内部指标，未经真实抽检不声称生产准确率；
- Python测试、Android几何测试和适用的模型导出冒烟测试通过。
