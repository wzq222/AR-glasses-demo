# 中车眼镜高准确率全图紧固件检测设计

## 1. 目标和验收门

目标是在手机上对整张巡检图做物理紧固件检测，随后只对检出的 ROI 判断类型、
色标几何和防松状态。检测阶段不再区分 `fastener` 和 `pipe_joint`，统一输出
`fastener_target`，避免类型互相竞争造成的漏检。

高准确率门在真实、完整全图、场景组隔离的封存测试集上计算：

- IoU 0.50 时 target-level recall 不低于 95%；
- 同一固定阈值下 target-level precision 不低于 90%；
- complete-scene rate（一张图内所有真实目标都被找到）不低于 90%；
- 封存测试集至少 30 个独立场景组和 200 个可判定目标；数量不足时不出具达门结论。

阈值只能在验证集上选择。封存测试集只在候选模型、权重、输入尺寸、NMS 和阈值
全部冻结后打开一次。如果未达门，该测试集降级为诊断集，必须采集新的外部场景建立
下一版封存测试，不允许反复调参到“通过”。

## 2. 当前证据和边界

当前已有 482 张真实现场图、177 个场景组。已训练银标覆盖 80 个完整场景、697 个框，
其中原始 train/val 为 64/16 场景。当前最优基线是 YOLOv8s-P2 640 全图：在已多次使用的
16 场景内部验证集上，物理目标合并 AP50 为 0.605、AR100 为 0.479；阈值 0.20 时
precision 0.641、recall 0.584。这只是失败基线，不是生产准确率。

482 张图来自同一次约 44 分钟采集。因此，本设计可在现有数据上建立严格的场景组
封存测试，但不能仅凭该测试声称跨车型、跨手机或跨光照的生产泛化。现有封存门通过后，
仍必须使用不同时间、不同车辆/设备和不同光照的新采集做外部验收。

## 3. 数据分区与防过拟合

以 `manifest.jsonl` 中的 `scene_group`、SHA-256 和原图路径为隔离边界。任意两个分区之间只要
共享场景组、文件哈希、图像 ID 或源路径，数据门立即拒绝训练。

预定分区如下：

- train：已有 64 个 train 场景，再从未训练场景中选 52 个，目标累计 116 个场景；
- val：已有 16 个 val 场景，再增 15 个，目标累计 31 个场景；
- sealed-test：从从未进入训练的场景中一次性冻结 30 个场景，不参与任何训练、
  伪标注自训练、阈值选择、输入尺寸选择或架构选型。

分区必须在标注前根据采集时间段、原始 train/val、清晰度、亮度、候选密度和设备外观做
确定性分层，不允许根据当前模型得分把“容易图”挑进测试集。每个场景初始只选一张代表全图；
同场景的相邻帧只能作为 train 增强，且使用 group-balanced sampler 限制每个场景的贡献，
防止拍摄频繁的机柜主导梯度。

训练阶段仅查看 train/val 指标。每个候选配置使用 3 个固定随机种子，同时报告均值、标准差和
最差种子，不允许只报最好的一次。早停只依据 val 的 `recall_at_precision_90`、AP50 和 loss；
最终权重的选择规则在封存测试打开前写入 run manifest。

## 4. 标注与质量控制

此阶段只在 Git 外数据资产目录建立新版 `annotations/high-accuracy-v1`，严禁修改现有
formal truth；每次运行前后都校验其指定 SHA-256。

离线教师使用高分辨率全图、重叠切片、当前 P2 学生、参考教师和 HSV 锚点生成建议框。
这些只是建议，不直接成为真值。每张全图必须经过：

1. 高清整图及重叠分块漏检扫描；
2. 逐候选首审，可独立界定的漏框必须补入；
3. 隐藏首审结论的几何二审；
4. 模糊、遮挡、边界截断或锚点归属不清时保留 `uncertain`，不强行标注。

Codex 可作为首审和盲审审核员，但两遍审核输入必须隔离，并保留审计 JSON、原图哈希和
决策理由。封存测试标注只用于最终评估，不向候选生成、训练或阈值调整流程暴露。

## 5. 模型优化路径

系统分为离线教师和手机学生两层：

- 离线教师：可使用更大 P2 检测头、960/1280 输入和重叠切片，优先提升建议框召回率；
  教师不进手机，也不能跳过审核写入真值。
- 手机学生：stride-4 P2 小目标头，默认 640 全图单次推理；仅当 val 证明 768 有稳定增益且
  手机性能可接受时才升级。切片仅作为低置信度或远小目标的条件回退，不作默认手机路径。

训练对照限定为三类，防止无限试模型：

1. P2-S 640 完整微调基线；
2. 在 train 上使用高召回教师做 box/logit distillation 的 P2-S 640；
3. 一个较大 P2 学生作为精度上限对照，仅在它显著超过 P2-S 时才考虑剪枝/蒸馏。

增强使用保守策略：受控亮度/对比度、轻度模糊、少量噪声、小角度旋转和有界缩放。
禁止会改变连接结构语义的激进 mosaic、大透视变形或随机裁掉主体。ImageGen 最多占 train 视图的
20%，只用于补充已由真实错误桶证明的稀有外观；不进 val、sealed-test 或任何验收统计。

## 6. 评估、误差闭环和停止规则

主指标为 `recall_at_precision_90`，辅助记录 AP50、AP75、COCO small recall、complete-scene rate、
每图误检数和三随机种子标准差。阈值、NMS 和输入尺寸全部只在 val 上冻结。

每一轮 val 的 FP/FN 自动归入以下错误桶：超小目标、暗部、遮挡、运动模糊、镜面反光、
管路密集、类似结构误检、边界截断和标注争议。只允许根据这些桶增加真实 train 数据或
调整增强，不根据 sealed-test 个例调参。

最多进行三轮训练数据闭环。如果 val 连续两轮的 recall 提升小于 1 个百分点，或三随机种子之间
的 recall 极差大于 5 个百分点，停止架构调参，转为补真实场景。封存门未通过时，不导出
“生产模型”，不接入 Android 默认流程。

## 7. 安全、授权和产物

所有 PyTorch 权重必须使用 `weights_only=True` 和审查过的 global allowlist 加载。训练图、标注、
权重、预测和评估产物全部留在 Git 外数据资产目录；Git 只保留方法、质量门、测试和无敏感
统计。

YOLOv8 系列当前仅作内部精度挑战者。商业交付前必须完成 Ultralytics AGPL/商业许可判定；
若授权不满足，使用同一数据门和评估门迁移到授权清晰的 P2 学生，不以更换框架为由放宽
准确率门。

达门后才生成带模型卡、输入/输出契约、阈值、评估集哈希和许可说明的 ONNX 产物，
随后接入 Android，在指定手机做连续 50 次热机推理，报告端到端 P50/P95、峰值内存、
温升和降频。
