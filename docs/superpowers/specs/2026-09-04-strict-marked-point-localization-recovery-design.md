# 严格防松检查点定位恢复设计

## 目标

在不修改正式真值、不打开sealed test的前提下，修复当前移动候选模型的小目标漏检、巨框和重复框问题。
内部验收必须使用一对一匹配：IoU 0.30召回优先，同时报告完整场景率、IoU 0.50召回和候选负担。

## 根因与单一假设

旧门把包含目标的大框计为命中，掩盖了定位问题；训练集虽然包含全图与切片，但每个训练场景只选择
1个切片，许多小检查点没有获得放大尺度监督。首个恢复实验只验证一个假设：覆盖全部4个重叠切片，
并沿用现有紧框真值与困难负样本，可以提高严格定位召回且不靠宽松匹配自证。

## 数据与训练

- train：`runs/marked-point-p2-e2/hard-negatives/instances.train.e2.json`；
- val：`annotations/marked-point-v1.4/instances.val.json`；
- 每个train场景物化1张全图和4张确定性切片；val仍只用原始全图；
- 从现有E2权重做低学习率单种子微调，禁止同时改变网络、增强和损失权重；
- 所有产物只写入Git外新目录，不覆盖旧运行。

## 验收与停止条件

使用全图、切片和融合三种推理口径，固定置信度搜索并执行一对一匹配。若IoU 0.30召回、完整场景率
或IoU 0.50召回没有相对当前基线改善，记录失败并停止该路线。只有IoU 0.30至少74/75且完整场景
至少16/17，才允许继续导出；达到75/75和17/17才允许作为新的高召回候选。手机替换后还要复跑
冻结17图与困难图库，不能用本开发集宣称生产准确率。

## 安全边界

正式真值SHA-256必须始终为
`B659FC8160BD7C49491BA4C560E1AF047CA837E54EE93E79826FEBAABCB0F001`。合成图不进入验证，
ImageGen不作为状态或定位准确率证据。严格门失败时保留当前人工复核流程，不替换APK模型。
