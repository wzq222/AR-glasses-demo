# 中车眼镜全图防松线视觉 V2 设计

## 决策

生产路线从“全图色标候选 → D-FINE-N”改为“物理紧固件检测 → ROI色标关键点 → 几何判断”。
`PicoDet-S 416`是手机基线，`PicoDet-M 416`是同运行时挑战者；二者必须在同一真值、同一切片策略和
同一手机上比较。RTMDet-tiny-P2、D-FINE-N、Grounded-SAM-2和DINOv3只在训练侧使用。

## 本阶段交付边界

本阶段建立四条可独立验证的链路：

1. 从177个场景组稳定选择100个代表帧，覆盖train/val、清晰度和HSV候选密度差异；结果写到Git外。
2. 为代表帧生成开放词汇建议框和可人工修正的COCO标注包；所有建议状态默认为`unreviewed`。
3. 只有至少80个场景组完成物理紧固件框复核、验证集非空且无跨组泄漏时，PicoDet训练入口才放行。
4. Android提供2×2重叠切片、原图坐标映射、框合并和端到端计时骨架；没有模型资产时明确返回
   `MODEL_UNAVAILABLE`。

本阶段不承诺松动分类准确率，也不把开放词汇模型建议框或HSV候选当作真值。受控正常/错位数据没有
补齐前，几何层保持`UNCERTAIN`。

## 数据契约

代表帧清单`selection-v2.json`记录选择版本、seed、目标数量、每张图的相对路径、scene_group、split、
focus_score、HSV候选数和选择原因。输出必须确定性可复现，同一场景组只选一张。

物理紧固件COCO类别第一轮固定为：

- `fastener`：螺栓、螺母及其可判定连接组合；
- `pipe_joint`：带防松标记的管接头连接。

每个annotation必须包含`review_status`，取值为`unreviewed / accept / reject / needs_manual`，并记录
`proposal_source`和`proposal_score`。训练导出只保留`accept`；`reject`是候选级否定，不转换成目标框。
无目标画面通过完成图像级`image_review_status=accept_empty`进入困难负样本。

## 代表帧选择

每个场景组先按清晰度、曝光可用性和候选密度选最佳帧，再按split配额与候选密度分层抽取场景组。
默认100组，其中train 80、val 20；若某split组数不足，保留至少10个val组，其余给train。选择器不得
读取文件绝对路径以外的私人内容，也不复制图片进Git。

## 建议框与复核

开放词汇试跑只使用代表帧中的12张分层样本，提示词固定为`bolt. nut. screw. fastener. pipe joint.`。
只有试跑人工抽检精确率不低于50%且明显漏框图占比不高于30%，才运行100张；否则停止批量推理，
直接生成无建议框的人工标注包。GroundingDINO/Grounded-SAM-2输出只用于节省画框时间。

复核包包含COCO JSON、逐图叠加图、联系表、`review-index.csv`和Label Studio任务JSON。任何修改通过
独立脚本合并，原始建议和人工决定都保留，避免覆盖审计证据。

## 训练与导出

PicoDet入口调用固定提交的PaddleDetection checkout，生成单类/双类数据配置，分别训练S和M，输出到
Git外`runs/picodet-{s,m}-v1`。入口在执行外部训练前验证：代表组数、复核完整性、train/val组隔离、
至少一个接受框、图像文件存在和类别合法。训练命令、提交、配置、数据哈希和环境写入run manifest。

首轮只比较目标召回、FP/图和模型端到端延迟；没有关键点真值时不训练ROI状态模型。

## Android切片契约

默认快速通路为一张416上下文图；完整通路附加2×2、边缘重叠12%的切片。切片坐标必须覆盖整图且
不会越界；模型框先映射回原图，再按类别做IoU NMS。耗时分为预处理、模型、合并和总耗时，连续50次
热机结果输出P50/P95。模型运行时通过接口注入，纯Java切片和合并逻辑不依赖Android Bitmap。

## 错误与安全门

- 缺资产、校验失败或运行时不支持：`MODEL_UNAVAILABLE`。
- 标注未完成、场景数不足或组泄漏：训练进程退出码2并写机器可读拒绝报告。
- 建议框试跑不达门：停止批量建议框，保留可手工标注的代表帧包。
- 单个图片解码失败：记录稳定错误码并继续其余图片；失败图不得悄悄计入已复核样本。
- 所有现场图片、标注和权重保持Git外；仓库仅存代码、统计、配置模板与不含现场内容的报告。

## 验收

- 选择器两次运行字节级一致，100张来自100个不同场景组，train/val无泄漏。
- 建议框试跑有明确PASS/FAIL报告，FAIL不会触发100张批处理。
- 训练门的每个拒绝条件有失败测试，干净真值样例能放行但默认不执行外部训练。
- 切片覆盖、坐标反变换、NMS和耗时分位数有纯单元测试。
- Python全量测试、Android单元测试和debug APK构建通过；无目标手机时明确记录未完成真机P95。
