# 手机端防松线松动状态评估设计

## 目标与边界

在现有全图紧固件候选检测之后，为手机测试应用增加可解释的防松见证标记状态评估。系统输出相对
位移角、测量不确定度和人工复核建议，优先保证松动候选召回，不把图像判断等同于预紧力、剩余扭矩
或结构安全结论。

首版只支持`bolt_head_plate`和`nut_plate`两类平面/近似平面拓扑。`nut_stud`、`double_nut`、
`fitting_pipe`和`clamp_pipe`在专用投影求解器完成前固定输出`INSUFFICIENT`。现有3°与15°仅为
研究支持的临时分诊阈值，生产配置继续保持`calibrated=false`。

## 方案选择

采用“全图轻量候选检测 + ROI多头分割/关键点 + 确定性几何 + 可选历史基准”的混合方案。

- 不采用纯颜色规则作为状态主算法：锈蚀、铜色、底漆和宽涂层已在真实图上造成错误拟合。
- 不采用直接`normal/loose`分类器：当前没有受控真实松动样本，分类器会学习背景与合成痕迹，且无法
  给出可审计的角度和拒判原因。
- 不照搬三套分割网络：共享一个轻量骨干，在一个ROI推理中输出零件、标记、接缝关键点和质量证据。

## 系统结构

### 1. 全图候选层

全图检测必须保留。短期沿用现有YOLOv8s-P2候选模型完成接口联调；并行训练YOLOv8n-P2学生模型，
以现有S-P2为教师进行蒸馏。学生模型只有在独立场景上达到既定候选召回门后才替换手机模型，不能仅
因为更快而降低输入尺寸或提高置信度阈值。

全图层只回答“哪里可能存在需要检查的带标记紧固点”，不输出松动状态。

### 2. ROI状态模型

每个候选框按长边1.5倍扩展并保持周围结构上下文，归一化到320×320。模型采用
`MobileNetV3-Small + LR-ASPP`作为首选，Fast-SCNN作为对照。共享骨干输出：

1. `fixed_part`、`moving_part`、`witness_mark`、`joint_boundary`四类语义掩膜；
2. 固定侧标记与接缝交点、活动侧标记与接缝交点，以及接缝椭圆/边界关键点；
3. 标记完整性、遮挡、模糊和拓扑置信度；
4. 端点热图的不确定度，不直接输出松/不松分类分数。

训练数据由现有24张合成三态提供几何监督，真实参考图只用于质量、拓扑和外观困难监督；未经受控
确认的真实图不得写成`ALIGNED/DISPLACED`状态真值。所有分区按物理场景或检查点分组，禁止同一点
的增强图跨train/val/test。

### 3. 几何求解器

求解器先根据`joint_boundary`拟合接缝线或椭圆，再把两段防松标记投影到物理接缝，计算两个交点的
相对转角`theta`。原图两条标记的表面方向差只作诊断信息，不直接作为松动角。

通过端点热图扰动、测试时增强和连续帧重复得到95%角度区间`[theta_low, theta_high]`。若三种估计的
拓扑、交点归属或角度互相冲突，结果固定为`INSUFFICIENT`。

在接缝近似圆形且参考尺寸为直径时，同时计算弦位移比`sin(theta/2)`作为交叉检查：3°约为0.0262，
15°约为0.1305。弦位移比不能替代拓扑投影，也不能继续使用任意两端点的最小距离近似。

### 4. 临时双阈值决策

规则按表格从上到下匹配，以消除边界重叠。在`calibrated=false`时，自动正式状态始终保持
`INSUFFICIENT`；下表中的`LIKELY_* / POSSIBLE_*`是`review_hint`分诊提示，不扩展正式四态契约。

| 条件 | 分诊提示 | 手机文案 | 是否要求人工确认 |
|---|---|---|---|
| 质量、拓扑、两侧归属或角度区间无效 | 无 | 无法判断，请靠近或换角度 | 是，需补拍 |
| `theta_high <= 3°`且标记完整 | `LIKELY_ALIGNED` | 未见明显错位 | 是 |
| `theta_low < 3° < theta_high` | `POSSIBLE_DISPLACED` | 结果跨越警戒线 | 是 |
| `theta_low >= 3°`且`theta_high < 15°` | `POSSIBLE_DISPLACED` | 可能错位 | 是 |
| `theta_low < 15° <= theta_high` | `POSSIBLE_DISPLACED` | 接近高疑似边界 | 是 |
| `theta_low >= 15°`且第二帧或第二视角一致 | `LIKELY_DISPLACED` | 高疑似错位 | 是，高优先级 |

在`calibrated=false`时，自动流程不得输出正式`ALIGNED`或`DISPLACED`。维护人员确认后可以记录
`HUMAN_CONFIRMED_ALIGNED/HUMAN_CONFIRMED_DISPLACED`，并保存确认人、时间、原图、ROI、模型版本、
角度区间和原因。人工确认结果进入受控真值候选池，但只有符合受控采集协议时才可进入训练真值。
`DAMAGED_MARK`同样只有在专用损伤模型完成真实标定或人工确认后才作为正式业务记录；临时模型仅给出
损伤复核提示。

### 5. 历史基准证据

若检查点有紧固验收图，先进行局部特征匹配与单应性配准，再计算当前交点相对基准的角度变化。
每个检查点使用健康重复拍摄建立临时控制限：

`T_point = max(3°, median(abs(delta_theta)) + 3 * 1.4826 * MAD)`。

历史基准与单图几何视为两个独立来源。只有两者都指向位移且人工确认后，记录才可升级为正式业务
异常。基准图更换、补漆、维修或紧固复位后必须建立新版本，旧版本只保留审计用途。

## 手机交互

相机预览继续实时显示，全图候选框使用橙色。用户点击或自动选择候选后，ROI状态推理异步运行：

- 绿色：`未见明显错位，待确认`；
- 黄色：`可能错位，待确认`；
- 红色：`高疑似错位，优先确认`；
- 灰色：`无法判断，请靠近/换角度`。

候选卡显示角度点估计、95%区间、图像质量、支持证据和耗时，并提供“确认正常”“确认错位”“无法
确认/重拍”三个按钮。未经人工确认的结果不得显示“安全”“合格”或“已松动”等确定性文案。

## 性能设计

ROI模型只对候选按优先级运行，不在每个相机帧上处理所有候选。首版目标是在P20 Pro上达到：

- 单个320×320 ROI INT8推理P50不超过250ms、P95不超过400ms；
- 全图候选与ROI状态串联后，首个选中检查点在3秒内给出结果；
- 连续运行10分钟无崩溃、无内存持续增长，并记录温度与降频；
- INT8与FP32在状态评估集上的角度误差增量不超过0.5°，状态路由不得产生额外“判正常”错误。

导出ONNX后分别测试CPU、XNNPACK和NNAPI，按目标手机实测结果选择后端。当前设备上已有NNAPI与
XNNPACK变慢的证据，因此不能默认启用硬件执行后端。

## 错误处理与安全策略

- 模型缺失、输出尺寸错误、非有限数值、坐标越界、掩膜为空或推理异常：`INSUFFICIENT`。
- 只检测到单侧防松线：`INSUFFICIENT`，绝不按正常处理。
- 标记破损与位移证据冲突：`INSUFFICIENT`并提示人工近拍。
- 连续帧差异超过3°或拓扑发生变化：丢弃缓存，要求重新稳定拍摄。
- 没有生产阈值配置或配置哈希不匹配：关闭自动正式状态，仅保留临时分诊。
- 日志不得保存原始现场图到Git；证据图和标注继续保存在Git外数据资产目录。

## 验证设计

### 单元与契约测试

- 3°和15°边界必须按表格精确路由，避免当前8°严格`>`的边界错误；
- 置信区间跨阈值必须进入人工复核；
- 未标定配置永不输出正式`ALIGNED/DISPLACED`；
- 单侧线、未知拓扑、低质量、非有限坐标、损伤冲突全部拒判；
- 透视变换前后，同一合成物理角的误差在允许范围内；
- INT8/FP32输出的关键点、角度和路由进行逐样本对照。

### 数据验证

正式标定使用至少10个真实物理检查点，由维护人员设置`0/2/3/5/8/10/15/20°`并恢复紧固；每个角度
覆盖正视、左右斜视，两种距离和明暗光照。数据按物理检查点划分，任何帧、增强图和同源裁剪不得
跨分区。

独立测试至少包含80个松动物理状态组，关键错误为真实错位被路由为`LIKELY_ALIGNED`。在没有满足
独立测试门前，只报告角度误差、候选召回、人工复核覆盖率和拒判率，不报告生产松动准确率。

### 真机验证

在P20 Pro上验证模型加载、候选点击、状态路由、重拍、人工确认、证据留存、前后台切换、相机权限
拒绝和10分钟热机。所有现场准确率结论必须绑定模型、阈值配置、测试集和APK SHA-256。

## 交付顺序

1. 先实现双阈值、不确定度和未标定分诊契约，替换8°测试夹具。
2. 建立ROI掩膜/关键点数据契约与合成训练基线。
3. 训练MobileNetV3-Small LR-ASPP与Fast-SCNN对照，选择角度误差和手机速度更优者。
4. 接入Android候选点击、状态显示和人工确认。
5. 采集受控真实角度数据，重新标定阈值并打开独立测试。
6. 训练并蒸馏全图YOLOv8n-P2，满足候选召回门后替换当前S-P2。
