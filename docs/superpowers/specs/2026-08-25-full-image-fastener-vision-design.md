# 中车眼镜全图防松线视觉设计

## 目标与非目标

本设计交付一个可在 Android 手机上离线运行的全图视觉管线：输入一张眼镜或手机拍摄的完整照片，
自动找出所有带防松标记的紧固件，从原始分辨率裁剪目标，识别防松线关键点，并在全图上返回
`NORMAL`、`LOOSE` 或 `UNCERTAIN`。用户不需要手工框选目标。

第一轮只训练和验证“目标发现”和“防松线几何提取”。现有数据没有经人工或扭矩复核的松动真值，
因此第一轮不得把由人为几何规则生成的状态当成真实松动准确率。二维码、万用表和通用SOP不进入本设计。

## 已核验的数据边界

- 本地训练源包含482张JPEG，分辨率全部为2000×1500，文件内容哈希均不同。
- 文件名时间覆盖2024-05-29 11:14:56至11:57:43，属于一次约44分钟的连续现场采集。
- 至少存在多组连拍或感知近重复图像；训练、验证和测试不能按图片随机拆分。
- 图片包含多种螺栓、螺母和管接头，存在暗光、反光、倾斜、遮挡和浅景深。
- 当前没有可靠的正常/松动真值、设备点位ID、车辆ID或扭矩记录。
- 原图、人工标注、模型权重和中间产物保存在Git外的本地工作区；仓库只保存代码、配置、标注清单
  和不含现场图像的统计结果。

## 技术方案

### 1. 两级全自动推理

```text
完整照片
  -> 质量检查
  -> 全图紧固件检测
  -> 原图ROI裁剪
  -> 防松线关键点检测
  -> 几何与置信度判定
  -> 全图结构化结果与叠加图
```

一级生产模型采用带P2小目标层的RTMDet-tiny，标准输入为960×960；当图像缩放后预计目标短边不足
16像素或快速通路结果不满足质量门时，启用640×640、20%重叠的切片检测，并通过类感知NMS合并。
一级输出 `FASTENER_BOLT`、`FASTENER_NUT`、`PIPE_JOINT` 三类框、置信度和来源切片。

二级采用RTMPose-t风格的轻量关键点模型。每个一级框从原始图扩边20%后裁成256×256或384×288；
模型对螺栓/管接头输出两段防松线的4个端点，对螺母组合可输出第3段的2个附加端点。每个点包含
坐标、可见性和置信度。

### 2. 几何判定

判定层不依赖模型内部类别概率直接猜松动，而是从关键点计算：

- 两段防松线的无向夹角；
- 端点至加权拟合直线的归一化残差；
- 最近端点间距除以目标框对角线；
- 关键点可见性、ROI清晰度、目标尺寸和拍摄倾角质量分。

任何关键点不可见、置信度不足、目标尺寸不足或质量门失败时返回 `UNCERTAIN`。`NORMAL` 与
`LOOSE` 阈值只可用独立、受控真值集标定；在获得真值前，几何层只返回连续测量值和
`UNCERTAIN`，不生成伪业务结论。

### 3. 模型与运行时选择

生产基线为RTMDet-tiny-P2 + RTMPose-t + ncnn FP16。模型只使用卷积、归一化、激活、上采样和
常规检测/热图解码等移动端稳定算子。Android通过单一JNI运行时加载模型，复用输入输出缓冲区，
并保持模型常驻内存。

D-FINE-N以ONNX Runtime Android实现同一 `FullImageDetector` 接口，只作为挑战者。它只有在目标
手机上同时满足更低漏检率和延迟预算时才替换生产基线。

DINOv3不进入APK。权重访问与许可证获批后，它只用于训练侧的图像聚类、重复样本发现、难例选择和
可选教师蒸馏；该能力缺失不得阻塞训练主线。DEIMv2因当前许可证禁止商业使用，不进入项目代码。

## 自动标注与人工复核

### 1. 全图框预标注

先按文件名时间、感知哈希和视觉嵌入对482张图聚类，按场景组选取代表帧。预标注器融合三类信号：

1. 红色/黄色防松标记的HSV候选区域；
2. 形态学与Hough线段得到的标记方向；
3. 可选开放词汇检测器对 `bolt`、`nut`、`pipe joint` 给出的候选框。

候选框必须在原图叠加图和COCO JSON中同时保存。AI逐张检查代表帧的叠加图，修正类别、边界和漏框；
同一连续场景的相邻帧只允许通过光流/模板跟踪传播，传播结果仍需抽样复核。低置信度候选不自动进入
训练集。

### 2. 关键点预标注

在已确认ROI内通过颜色分割、连通域、骨架化和稳健直线拟合生成防松线端点。关键点叠加图使用固定
颜色区分移动件和固定件；无法确认哪一段属于哪一部件时标记为不可见，不猜测端点语义。

### 3. 数据拆分

数据按连续时间段和视觉场景组拆分，任何近重复组只能落在一个split。当前单次采集最多形成训练集和
内部验证集，不形成对外测试集。独立测试集必须来自另一车辆、点位或采集日期。

## 训练与选择门

训练工程使用Python、PyTorch、MMDetection和MMPose，数据契约采用COCO bbox + COCO keypoints。
首轮依次执行：

1. 用审核后的代表帧训练一级检测器；
2. 用审核后的ROI训练二级关键点模型；
3. 在内部验证集生成逐图预测、错误清单和可视化；
4. 导出ONNX，再转换为ncnn FP16；
5. 在同一批图和同一Android手机上比较生产基线与D-FINE-N挑战者。

模型选择指标按优先级排序：目标漏检率、关键点PCK、松动召回率、`UNCERTAIN`率、P95整图延迟、
峰值内存、模型体积。没有真实松动标签时不计算松动召回率。

## Android契约

现有 `boolean isNutLoose(Bitmap)` 被保留为兼容层，但新代码不得以它承载全图结果。新契约为：

```java
FullImageInspectionResult inspectFasteners(Bitmap bitmap);
```

`FullImageInspectionResult` 包含图像尺寸、算法版本、总耗时、质量状态和多个
`FastenerInspection`。每个目标包含原图坐标框、类型、检测置信度、关键点、几何测量、状态、
是否需要人工复核和稳定错误码。

Android实现拆成可独立测试的组件：图像变换、切片生成、框合并、ROI映射、几何判定、模型运行时和
结果绘制。UI只消费结构化结果，不解析模型张量。

## 错误处理

- 模型资产缺失或校验失败：`MODEL_UNAVAILABLE`，不回退到“未松动”。
- 图像过暗、模糊或分辨率不足：`IMAGE_QUALITY_LOW`。
- 全图没有目标：`NO_FASTENER_FOUND`，与正常结果区分。
- 目标存在但防松线不可见：该目标返回 `UNCERTAIN` 和 `MARK_NOT_VISIBLE`。
- 单个ROI失败不终止其他目标；整图结果保留部分成功和逐目标错误。

## 测试与验收

纯Java单元测试覆盖切片边界、坐标反变换、NMS、关键点映射、夹角/共线度/间距和不确定性门控。
Python测试覆盖COCO数据校验、场景组拆分、近重复隔离、模型输出契约和导出数值一致性。Android仪器
测试使用小型合成模型验证JNI加载、Bitmap预处理、并发取消、内存释放和结构化结果。

第一阶段验收条件：

- 对审核数据生成完整COCO框和关键点标注清单及可视化复核包；
- 检测与关键点训练可复现，验证集结果按场景组统计；
- Android项目可在没有真实模型时明确报错，在装入测试模型后完成全图多目标数据流；
- 真机性能记录包含手机型号、Android版本、线程数、每图目标数、P50/P95和峰值内存；
- 对外不宣称松动准确率，直到独立受控松动集完成。
