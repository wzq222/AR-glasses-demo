# 物理紧固件候选去重设计

## 目标

在不修改正式真值的前提下，把多尺度、切片和多来源检测对同一物理紧固件产生的重复框合并，降低全图审核负担；相邻独立紧固件必须保持分离。

## 现状与根因

当前 `fuse_candidates` 使用 `IoU >= 0.55` 的单链连通聚类。它有两个缺陷：

1. 同一实体的大框与小框存在明显包含关系，但 IoU 较低，无法合并。
2. 单链聚类允许 A 匹配 B、B 匹配 C 后把 A 与 C 间接合并，存在把相邻实体串起来的风险。

现场复核中，图 0007 的 15 个融合候选主要集中在少量连接件，图 0047 的 10 个候选主要集中在 3 个带防松标记的紧固件，证明当前融合候选数不能代表独立物理对象数。

## 方案比较

### 方案 A：直接降低 IoU 阈值

实现最简单，但相邻螺栓、螺母与接头容易被误合并，拒绝采用。

### 方案 B：仅增加包含率判定

可以解决嵌套框，但大框覆盖两个相邻实体时仍可能误合并，风险仍高。

### 方案 C：保守复合判定与完全链接（首轮实现，真实数据门拒绝）

候选满足以下任一条件才视为几何重复：

- `IoU >= 0.55`；或
- 交集占较小框面积的比例达到严格阈值，同时中心距离足够小、面积比例不过大。

首轮聚类使用完全链接约束：新候选必须与簇内每个成员都满足重复条件，禁止单链桥接。不同类别的严格重叠候选仍合并为 `conflict`，交给审核决定，不静默选类。

真实数据门表明完全链接过严：v2 全量融合候选由 v1 的 5535 增至 5617，图 0007 仍为 15，图 0047 仍为 10。同一管接头的教师框被拆成 `5+2`，同一紧固件的教师框被拆成 `8+1`，因此该首轮实现保留为审计证据但不得恢复批量审核。

### 方案 D：教师锚点与唯一归属（修订采用）

1. `reference_teacher` 多尺度候选先按确定性顺序形成物理锚点。候选与簇的固定来源代表框比较，不允许新成员把锚点沿 A-B-C 链移动；同一实体的尺度离群框只要匹配代表框即可归簇。
2. HSV 候选的 `180×180` 框是防松标记搜索窗口，不等同于紧固件物理框。使用窗口中心作为标记点，仅当该点落在一个教师锚框内或其 5% 对角线扩展区，并且最优、次优锚点的归一化中心距离差至少为 0.10 时，才唯一归属。
3. 同时落入多个相近锚点且没有足够距离优势时保持独立，交给审核；不得依靠降低全局 IoU 强行合并。
4. 未归属的 HSV、时序和学生候选继续使用保守几何聚类。跨类别归属仍输出 `conflict`。

只读模拟结果为全量 4665、图 0007 为 12、图 0047 为 7；该结果仅用于选择算法，必须通过测试先行实现并重新生成不可覆盖的 `v2.1` 资产后才可作为正式结论。

## 数据流

1. 保留原始 `safe-auto-candidates-v1` 作为审计证据。
2. 使用确定性排序、教师锚点和唯一归属生成新的候选输出目录，不覆盖旧产物；首轮拒绝的 v2 也保留。
3. 输出合并前后候选数、簇大小分布和正式真值前后哈希。
4. 用新候选生成新的 Git 外复核包；已完成场景不重复审核。
5. 先对图 0007、0047及相邻双螺栓反例做回归验证，再恢复每批 6 train / 2 val 的全图审核。

## 安全边界

- 不读取审核结论来调参，避免验证集泄漏。
- 不修改 `annotations/fastener-v2/instances.json`。
- 不覆盖现有候选、复核包或累计 reviewed COCO。
- 不因去重自动接受候选；去重只减少审核单元，完整性仍由高清全图扫描确认。
- 无法确定是否同一实体时保持分离。

## 测试与验收

测试先行，至少覆盖：

1. 尺寸不同但中心一致的嵌套框合并。
2. 相邻独立螺栓不合并。
3. 同源教师框 A-B、B-C 重叠但 A-C 不匹配时不得链式合并。
4. 输入顺序变化不影响候选 ID 和输出顺序。
5. 跨类别严格重叠仍输出 `conflict`。
6. HSV 标记点唯一落入一个教师锚点时归属，落入两个相邻锚点且无距离优势时保持独立。
7. 全量 Python 测试通过。
8. 图 0007、0047的独立审核单元明显减少，且人工查看没有实体合并错误。
9. 正式真值 SHA-256 保持 `B659FC8160BD7C49491BA4C560E1AF047CA837E54EE93E79826FEBAABCB0F001`。

只有以上条件全部满足，才恢复自动批次审核。
