# 中车眼镜防松标记点多帧高召回设计

## 1. 业务目标

系统在眼镜连续采集的 2–5 张全图中，自动找到所有**带红、黄等防松标记且需要判断状态的
检查点**，合并重复目标，并输出每个检查点的防松标记状态。普通螺栓、未标记管接头和相似结构
不属于业务目标，只能作为困难负样本。

“全图检测”指系统扫描每张输入图的完整像素范围，不要求用户手工框选 ROI。系统允许通过多帧
覆盖同一作业区域，并将多帧结果合并成一次检查。它判断的是防松标记是否连续或错位，不能直接
证明真实扭矩；产品文案使用“防松标记正常/异常/不可判”，不声称测得螺栓扭矩。

输出固定为：

- `NORMAL`：标记跨固定侧和活动侧连续，且几何量在现场标定阈值内；
- `LOOSE`：标记发生可重复观测的角度、间隙或拟合残差越界；
- `UNCERTAIN`：目标、标记、两侧归属、图像质量或阈值任一不可靠。

## 2. 为什么停止旧路线

上一版把带标记检查点、普通紧固件、管接头和部分相似结构合并为一个 `fastener_target`。
严格验证中的 70 个 FN 因而混合了业务漏检和非业务目标漏检，模型被要求学习互相冲突的边界。
扩大 YOLOv8s-P2 到 M-P2 没有改善，证明继续增加单阶段模型容量不是当前最小有效动作。

旧版 high-accuracy-v2 sealed-test 的目标定义已不匹配新业务口径。它保持未打开并归档为历史
物理目标集，不用于新路线的模型选择或最终验收。新路线必须从新采集、实体隔离的数据建立新的
marked-point sealed-test。

## 3. 推荐架构

### 3.1 数据流

```text
眼镜 2–5 帧
  -> 质量与覆盖门
  -> 选取每个覆盖区域最清晰帧
  -> A路：红/黄标记高召回候选
  -> B路：低阈值通用紧固件候选
  -> 候选并集与跨帧去重
  -> ROI 标记点复核
  -> 标记掩码/端点与两侧归属
  -> 几何状态判定
  -> NORMAL / LOOSE / UNCERTAIN + 证据图
```

系统不在所有帧上无差别执行全部神经网络。廉价的质量、颜色和运动分析先运行；通用检测器只在
最清晰关键帧及未覆盖区域运行，状态模型只处理候选 ROI。这样把算力集中在可能的检查点上。

### 3.2 采集质量与覆盖门

采集管理器对每帧计算曝光、Laplacian 清晰度、运动模糊、遮挡和与上一帧的有效重叠。按图像网格
维护覆盖状态，每个网格至少保留一张质量达门的帧。重复视角只保留最清晰帧；视角变化过大或
覆盖不足时提示补拍，不把“没有拍清楚”当成“没有异常”。

多帧对应关系优先使用局部特征匹配和单应性；存在明显视差时不强行整图配准，改为在候选级使用
位置、局部描述子和外观相似度关联。无法稳定关联的目标分别保留，交给后续去重门或输出
`UNCERTAIN`。

### 3.3 A路：防松标记直接候选

A路以召回为唯一优先级，组合两个来源：

1. HSV/Lab 多颜色区间、局部对比度和细长连通域产生确定性候选；
2. 轻量标记分割模型识别褪色、阴影、污渍和非标准颜色下的防松漆。

两个来源取并集，不在候选层追求高 precision。颜色阈值按设备或现场配置保存，不写死成全局真值。
模型输出标记掩码和可见度，DINOv3只用于离线难例聚类、特征检索和教师辅助，不进入手机推理链。

### 3.4 B路：通用紧固件补漏

B路使用授权清晰、带 stride-4/P2 小目标头的轻量检测器，以低阈值扫描关键帧和未覆盖网格。
它可以检出所有可能的螺栓、螺母和管接头，但这些结果不是最终业务结果。只有在 ROI 内发现
可信防松标记后才转成检查点。

现有 P2 权重只作候选初始化，不直接作为生产模型。首轮在 PicoDet-S-P2 与一个 Apache-2.0
兼容的轻量 P2 检测实现之间做同数据、同输入、同阈值的有界对照；选择规则先看候选 recall，
再看手机时延，不使用 AP50 替代业务召回。

### 3.5 候选融合与 ROI 复核

A/B 两路候选先在单帧内用包含关系和 IoU 聚类，再在多帧间按几何映射与局部特征去重。每个候选
保留来源、帧号、原图坐标、质量分和所有原始分数，禁止只保留最高分而丢失补漏来源。

ROI 复核器输出：

- `MARKED_POINT`：紧固件与防松标记属于同一检查点；
- `UNMARKED_FASTENER`：真实紧固件但没有业务标记；
- `LOOKALIKE`：贴纸、锈斑、反光、线缆、孔洞等相似结构；
- `UNCERTAIN`：信息不足。

复核器使用高分辨率 ROI，训练时显式加入当前 tiny、lookalike、dense-pipes、blur 错误桶。
候选层阈值只允许由 recall 门决定；最终 precision 由 ROI 复核器承担。

### 3.6 防松状态模型

对 `MARKED_POINT` ROI 运行轻量分割/关键点模型，输出：

- 固定侧标记掩码或两端点；
- 活动侧标记掩码或两端点；
- 两侧归属置信度；
- 标记可见性、遮挡和截断标志；
- 参考尺寸。

现有 `AntiLooseGeometry` 计算无向夹角、归一化端点间距和共同直线残差。只有来自受控真值集的
阈值才允许输出 `NORMAL` 或 `LOOSE`；未标定、低置信度、只看到单侧标记、严重反光或多帧结论
冲突时输出 `UNCERTAIN`。多帧状态采用证据一致性规则：至少两帧可判且结论一致，或者一张显著
更清晰的主帧通过更高置信度门；否则不自动判正常。

## 4. 新数据契约

每个业务目标至少包含：

- `physical_instance_id`：同一真实检查点跨帧保持一致；
- 全图 bbox 和可见比例；
- `marked_point / unmarked_fastener / lookalike / uncertain`；
- 防松标记像素掩码；
- 固定侧与活动侧的线段端点及归属；
- `NORMAL / LOOSE / UNCERTAIN` 状态及可审计理由；
- 车辆、设备、位置、采集批次、光照和相机元数据；
- 首审、隐藏结论二审和原图 SHA-256。

现有 train/val 图像可以重新标注为开发集，但只允许使用未封存图像。旧普通紧固件框转换为
`UNMARKED_FASTENER` 困难负样本，不计入业务召回分母。状态训练必须加入同一实体的受控成对数据：
维护人员确认的正常状态，以及按安全规程制造并记录位移后的异常状态。ImageGen只可补颜色、污渍
和光照外观，不得生成状态真值，不进入 val 或 sealed-test。

数据按车辆/设备/物理实例/采集批次联合分组，任一实体不得跨 train、val、test。新 sealed-test
必须来自不同时间或不同车辆，冻结模型、阈值、输入尺寸和融合规则后只打开一次。

## 5. 验收指标

在 marked-point val 上依次过门：

1. A/B 并集候选 recall `>= 0.99`；
2. 最终标记点 recall `>= 0.97`、precision `>= 0.95`；
3. 完整场景率 `>= 0.95`；
4. 在可判状态子集上，`LOOSE` recall `>= 0.95`、`NORMAL` precision `>= 0.95`；
5. 同时报端到端状态召回、`UNCERTAIN` 率和多帧冲突率，不只报条件状态准确率；
6. 三个固定随机种子的最终标记点 recall 极差 `<= 0.03`。

最终门在新 sealed-test 上使用同一冻结阈值。少于 30 个独立场景、200 个标记点、50 个受控
异常点或 50 个受控正常点时，只报告研发指标，不出具高准确率结论。

## 6. 手机性能预算

目标为离线运行：

- 普通流程端到端 P95 `<= 3 s`；
- 触发高清补扫的疑难流程 P95 `<= 8 s`；
- 连续 50 次检查无崩溃、内存持续增长或明显热降频；
- 结果必须保留原始帧、检查点框、状态证据 ROI、模型版本和阈值版本。

性能优化顺序固定为：减少重复帧和无效网格、批量 ROI、整数或 FP16 推理、模型量化；不通过提高
候选阈值牺牲 recall。指定手机实测前，桌面 GPU/CPU 时延不作为手机性能证据。

## 7. 失败处理与安全边界

- 覆盖不足：要求补拍，不输出“全部正常”；
- 候选过多：分批 ROI 复核并提示延时，不截断低分候选；
- 图像模糊或过暗：选择其他帧，全部不达门则输出 `UNCERTAIN`；
- 两路冲突：保留并进入 ROI 复核，不能以来源优先级直接删除；
- 多帧状态冲突：输出 `UNCERTAIN` 并保存冲突帧；
- 模型或阈值版本不匹配：拒绝状态判定；
- 许可未解决：研究权重不得进入商业 Android 包。

## 8. 实施切片

### Slice 1：重定义真值并证明候选可行

从未封存开发图中选取覆盖主要错误桶的代表场景，重新标注 marked/unmarked/lookalike，生成颜色
候选与低阈值 P2 候选的并集。只有候选 recall 达到 0.99 才进入下一步；否则优先补候选来源，
不训练状态模型。

### Slice 2：ROI 复核与多帧去重

训练标记点复核器，接入关键帧选择和候选级跨帧去重，验证最终检测 recall/precision、完整场景率
及 3 秒性能预算。

### Slice 3：防松线分割与受控状态集

制作受控 NORMAL/LOOSE 成对样本，训练两侧标记分割/关键点模型并标定几何阈值。端到端状态门
未通过时，产品只能展示检查点和 `UNCERTAIN`。

### Slice 4：Android闭环与新封存测试

在授权、检测门和状态门都通过后接入 Android，完成眼镜多帧采集、证据留痕、50 次热机测试，
最后一次性打开新 marked-point sealed-test。
