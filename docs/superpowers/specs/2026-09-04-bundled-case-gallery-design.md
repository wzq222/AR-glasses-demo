# APK 内置案例图库设计

## 目标

在不修改检测模型的前提下，将用户提供的 7 张案例图片打入调试 APK，使覆盖安装后无需再次
从手机系统图库导入，即可在 SOP 每一步的“从原图库选择”入口中选择并运行识别流程。

## 方案

构建时通过 `CRRC_BUILTIN_GALLERY_DIR` 指向 Git 外案例目录。Gradle 只把 JPEG、PNG 和 WebP
复制到本次 APK 的生成资产目录，现场图片不进入 Git。APK 内保留 `qr`、`fastener`、`meter`
子目录和原始文件名。

`GalleryActivity` 在后台将 APK 的 `assets/builtin_gallery` 安全释放到 App 内部只读案例目录，
然后把该目录与现有 `glass_media/photos` 一起展示。现有眼镜同步照片和用户导入图片不移动、
不覆盖；案例释放失败时仍显示原图库已有图片并给出提示。

## 安全与幂等

- 只接受普通相对路径和 `.jpg/.jpeg/.png/.webp`；拒绝绝对路径、空段和 `..`。
- 每张图片先写 `.part`，成功后原子替换，避免中断留下半张图。
- 已存在且字节数一致的案例不重复写入。
- APK 内置案例与外部原图库使用不同根目录，因此不会覆盖同名现场照片。
- 模型、阈值、formal truth 和后台数据均不变。

## 验收

1. 单元测试证明递归释放、幂等、过滤非图片和路径安全。
2. Android 全量单元测试与 Debug 构建通过。
3. APK 压缩包中存在二维码 1 张、防松线 1 张、万用表 5 张。
4. 有 ADB 设备时覆盖安装并核验原图库显示 7 张内置案例；没有设备时明确只交付 APK。
