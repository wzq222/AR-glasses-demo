# 防松检查点重框与高召回矛盾研究

## 决策

暂停模型、阈值和 Android APK 变更。当前版本继续作为冻结基线，不将本轮 E5/E6
实验权重提升为手机模型，也不靠更强 NMS 隐藏问题。

用户指出的重框现象并非单纯“去重参数不够强”，而是三个问题叠加：

1. 检测器只有在极低置信度下才能找齐困难检查点，背景候选同时爆炸；
2. 多尺度切片对同一物体产生重复框、偏移框和大区域框；
3. 现有第二阶段是 ROI 分类器，能判断裁剪像不像检查点，但不能把宽松框回归为紧框。

因此，继续调 NMS 会在相邻螺栓之间产生不可接受的召回损失。应把“候选召回”、
“紧框定位”和“防松线状态”作为三个独立验收层。

### 阈值为什么解不开矛盾

E6 切片候选的代表性阈值曲线：

| 置信度阈值 | IoU 0.30 覆盖 | 完整场景 | 候选/图 |
|---:|---:|---:|---:|
| 0.00010 | 75/75 | 17/17 | 217.1 |
| 0.00015 | 74/75 | 16/17 | 159.1 |
| 0.00100 | 67/75 | 13/17 | 29.1 |
| 0.00500 | 55/75 | 6/17 | 11.4 |
| 0.01000 | 54/75 | 5/17 | 8.4 |

这说明困难真目标与大量背景在分数上没有分开。把阈值抬到手机可操作的候选数量时，
漏检已经发生；把阈值降到全召回时，任何融合或 NMS 都要在数千个互相嵌套的框上作决定。

### NMS 为什么不能单独解决

- 同一检查点的重复框可以合并；
- 一个覆盖多个相邻检查点的大框不能安全归属于任一检查点；
- 密集区域里真实相邻螺栓本来就有较高重叠，强行提高抑制会吞掉真实目标；
- 当前 verifier 只输出语义分数，不输出新的中心、紧框或掩膜，无法修复定位。

所以“源感知融合/包含关系抑制”只适合清理明显重复，不能作为准确率修复手段。

## 推荐技术路线

### 第一阶段：高召回区域提议

保留一个轻量 P2 检测器作为粗召回器，但输出的是待放大的检查区域，不直接作为最终检查点框。
全图和切片结果先按空间邻域形成非破坏性的 review region；聚类只负责调度计算和界面分页，
不得删除簇内候选。

### 第二阶段：定位感知的 ROI 模型

把二分类 verifier 替换为小型定位头，在扩大后的原图 ROI 内重新输出：

- 紧固件中心或紧框；
- 防松标记掩膜；
- 固定侧/活动侧或接缝关键点；
- 证据质量和不可判断原因。

推荐优先比较“小型 P2 检测头”和“中心关键点 + 掩膜头”，而不是继续训练纯分类器。
第二阶段必须用紧框、邻接螺栓、宽框、重复框、红黄贴纸、导线和高光等显式硬负样本训练。

### 第三阶段：状态几何与人工审核

只有紧框和标记掩膜通过质量门，才计算固定侧与活动侧两段线的夹角、间隙和连续性，输出：

- 对齐；
- 可能松动；
- 高疑似松动；
- 无法判断/需要补拍。

3°/15°当前只能用于实验分诊，不能作为生产真值阈值。生产标定必须来自同一物理点的受控
`0/2/3/5/8/10/15/20°` 成对照片；合成图只做外观增强，不用于证明阈值或准确率。

## 数据缺口与验收门

当前 marked-point 定位集只有 30 个 train 场景、17 个 val 场景。下一次恢复模型工作前，先完成：

1. 再补至少 34 个独立 train 场景，重点覆盖密集机柜、斜视、模糊、遮挡、小目标和强反光；
2. 对检查点做紧框/中心和防松标记掩膜标注，而不仅是“框内存在目标”；
3. 将宽框、跨目标框和 lookalike 作为明确负样本；
4. 保持物理场景隔离，合成变体不得跨 train/val；
5. sealed test 在模型与阈值冻结前不得打开。

下一轮模型只有同时满足以下开发门才允许进入 APK：

- 一对一 `IoU >= 0.30` 召回至少 74/75（98.7%）；
- 完整场景至少 16/17；
- `IoU >= 0.50` 单独报告且不得比当前严格基线退化；
- 最终人工候选不超过 20/图，另报告 P50/P95 和最大值；
- `lock-real-01` 等密集场景不得出现跨多个检查点的大框作为最终结果；
- 独立跨车辆/设备/光照测试通过后，才允许表述生产准确率。
