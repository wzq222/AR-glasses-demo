# 全图紧固件高准确率验证收口

## 结论

当前算法**没有达到高准确率交付门**。在冻结的 19 个验证场景、108 个物理紧固件上，
最佳结果来自 YOLOv8s-P2 seed `20260829` 的全图与 2×2 切片融合：在
`precision >= 0.90` 的约束下，precision 为 `0.9048`，recall 为 `0.3519`，
19 个场景中完整检出的场景为 0。目标门为 recall `>= 0.95`、precision `>= 0.90`、
complete-scene rate `>= 0.90`，因此差距很大。

30 个封存测试场景保持未打开。验证门未通过时打开封存集只会消耗一次性测试资产，
不会产生可交付模型，所以本轮按预设停止规则拒绝打开，也没有接入 Android。

## 数据边界

- train：78 个独立场景、638 框；
- val：19 个独立场景、108 框；
- sealed-test：30 个独立场景、276 框；
- 全部标注合并为单一物理目标类 `fastener_target`；
- formal truth SHA-256 始终为
  `B659FC8160BD7C49491BA4C560E1AF047CA837E54EE93E79826FEBAABCB0F001`；
- sealed-test COCO 只做过文件哈希核对，未生成预测、未读取指标，`sealed_test_opened=false`。

现有 127 个完整场景仍来自同一次约 44 分钟采集，不能代表跨车型、跨设备、跨光照泛化。

## 严格验证结果

所有结果均在 IoU 0.50、单一物理目标类下，用验证集选择能满足
`precision >= 0.90` 的最高 recall 阈值。`fused` 为全图与确定性 2×2 重叠切片融合。

| 模型 | seed | 模式 | 阈值 | precision | recall | TP / FP / FN | 完整场景 |
|---|---:|---|---:|---:|---:|---|---:|
| YOLOv8s-P2 | 20260828 | full | 0.8434 | 0.9130 | 0.1944 | 21 / 2 / 87 | 0 / 19 |
| YOLOv8s-P2 | 20260828 | fused | 0.8728 | 0.9167 | 0.2037 | 22 / 2 / 86 | 0 / 19 |
| YOLOv8s-P2 | 20260829 | full | 0.7946 | 0.9231 | 0.2222 | 24 / 2 / 84 | 0 / 19 |
| YOLOv8s-P2 | 20260829 | fused | 0.7443 | 0.9048 | **0.3519** | 38 / 4 / 70 | 0 / 19 |
| YOLOv8s-P2 | 20260830 | full | 0.7526 | 0.9000 | 0.2500 | 27 / 3 / 81 | 0 / 19 |
| YOLOv8s-P2 | 20260830 | fused | 0.7997 | 0.9032 | 0.2593 | 28 / 3 / 80 | 0 / 19 |
| YOLOv8m-P2 | 20260829 | full | 0.7040 | 0.9000 | 0.1667 | 18 / 2 / 90 | 0 / 19 |
| YOLOv8m-P2 | 20260829 | fused | 0.8680 | 0.9000 | 0.0833 | 9 / 1 / 99 | 0 / 19 |

S-P2 的 full recall 三种子均值为 `0.2222`，极差为 `0.0556`；fused 均值为
`0.2716`，极差为 `0.1481`。两种模式都未通过预设的 `<= 0.05` 稳定性门。
M-P2 在同一 seed 上没有比 S-P2 提升至少 0.03，反而明显下降，因此按计划不再训练
其余 M 种子，也不启动蒸馏。

M-P2 完成了 30 个 epoch；Ultralytics 8.2.40 在最终剥离优化器时与 PyTorch 2.7.1
的 `weights_only` 默认值不兼容。训练产生的本地 best checkpoint 已用受限 global allowlist
安全加载并完成上述评估，运行清单保留了该 finalization error，不能把它误写成完整导出权重。

## 误差诊断

对最佳 S-P2 fused 结果使用选择清单中的精确阈值 `0.7443283200263977` 生成了
验证集误差包。共 74 个错误：70 FN、4 FP。主错误桶为：

- tiny：33；
- lookalike：21；
- dense pipes：8；
- blur：7；
- border truncation：4；
- dark：1。

进一步检查 108 个真值目标：13 个即使把置信度降到 0.001 也没有 IoU >= 0.5 的候选；
57 个有候选但分数低于 P90 阈值；38 个在阈值以上。主要矛盾是微小真目标和相似结构之间的
置信度分离，次要矛盾是小目标定位。继续增加模型容量没有解决这一问题。

## 防松线“松 / 不松”能力

Android 端已有经过单元测试的 `AntiLooseGeometry`：输入两段防松线端点、参考尺寸和
现场标定阈值后，可输出 `NORMAL / LOOSE / UNCERTAIN`，低置信度或未标定阈值强制输出
`UNCERTAIN`。但这只是几何判定核心，不是端到端图像算法。

当前 1,022 个框只标注了紧固件位置，没有防松线端点、可见性和受控 `NORMAL / LOOSE`
状态；`DefaultImageAnalyzer.isNutLoose(Bitmap)` 仍是占位实现。因此当前不能识别并证明
“松不松”，也不能给出状态准确率。用现有照片或 ImageGen 猜状态会制造伪真值，不进入训练或验收。

要完成状态闭环，必须新增受控样本：同一紧固件在已确认正常和按规定角度/扭矩产生位移后的成对照片，
标注两段线端点、可见性、遮挡、参考尺寸和状态，并按实体隔离 train/val/test。之后训练 ROI 内
关键点/线段模型，在独立测试集上单独报告松动召回率、正常精确率和 `UNCERTAIN` 率，再标定
`AntiLooseGeometry` 阈值。

## 工程决定

1. 不打开 sealed-test，不发布“高准确率”结论。
2. 不把当前 YOLO 权重接入 Android；精度门与 Ultralytics 商业授权均未解决。
3. 停止继续轮换 S/M 架构。下一轮只在新增真实独立场景后启动，优先补 tiny、lookalike、
   blur、dense-pipes 和不同车型/设备/光照。
4. 防松状态先采集受控正常/松动对和线端点真值；没有该证据时生产输出只能是 `UNCERTAIN`。
