# 防松检查点定位门纠偏

## 结论

旧 `marked-point-model-gate-v2` 使用“候选中心落入真值，或 IoU >= 0.10，或包含率
>= 0.50”的宽松匹配，且同一候选可同时覆盖多个真值。这会让覆盖大片画面的框被计为
成功召回，也会把巨框裁剪训练成复核模型的正样本。因此先前的 `75/75` 只是宽松候选覆盖，
不是准确定位。

门已升级为 `marked-point-model-gate-v3`：

- 候选与真值必须 IoU >= 0.30；
- 执行确定性一对一匹配，一个候选不得代表两个相邻检查点；
- 复核训练样本只接受紧框，巨框不再因“包含真值”成为正样本；
- IoU 0.50 仍作为更严格的定位质量指标单独报告。

## 重新审计

冻结的 17 张开发验证图共 75 个检查点：

| 候选源 | IoU >= 0.30 | 完整场景 | IoU >= 0.50 | 完整场景 |
|---|---:|---:|---:|---:|
| 当前 512 marked-point 原始候选 | 68/75 | 12/17 | 62/75 | 11/17 |
| 当前手机复核后候选 | 62/75 | 8/17 | 40/75 | 3/17 |
| marked-point e2 融合候选 | 72/75 | 15/17 | 67/75 | 12/17 |
| all-fastener v9 全图+切片融合 | 73/75 | 15/17 | 68/75 | 14/17 |
| e2 + v9 教师并集 | **75/75** | **17/17** | 72/75 | 15/17 |

因此当前手机模型严格门为 FAIL，不得宣称防松检查点定位已完成。`e2 + v9`
可作为 IoU 0.30 下的高召回教师组合，但其候选量和移动端延迟不适合直接交付；下一步是使用
紧框真值和巨框/重复框硬负样本蒸馏为单个移动端模型。
